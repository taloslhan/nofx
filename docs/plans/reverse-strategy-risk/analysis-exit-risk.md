# 平仓风控 -- 独立止损与利润保护

## 1. 核心原则: 平仓不依赖AI

反向策略的平仓应建立独立的止损/止盈机制:
- AI的平仓信号可以作为参考（不反向），但不是唯一依据
- 交易所端SL/TP订单提供硬保护
- 多层平仓机制确保没有"孤儿仓位"

## 2. 独立止损机制

### 2.1 三层止损架构

```
Layer 1: 交易所端 SL/TP 订单（硬保护）
    ↓ 如果SL/TP未触发
Layer 2: 程序端追踪止损/时间止损（软保护）
    ↓ 如果程序端也未触发
Layer 3: AI平仓建议（参考信号，不反向）
```

### 2.2 Layer 1: 交易所端订单

现有代码在开仓后立即设置SL/TP:
```go
at.trader.SetStopLoss(decision.Symbol, "LONG", quantity, decision.StopLoss)
at.trader.SetTakeProfit(decision.Symbol, "LONG", quantity, decision.TakeProfit)
```

反向策略的SL/TP设置（使用方案B: 基于ATR自行计算）:
```
开空后:
  SL = entryPrice x (1 + 1.5 x ATR%)     // 价格上涨1.5倍ATR止损
  TP = entryPrice x (1 - 1.0 x ATR%)     // 价格下跌1.0倍ATR止盈

开多后:
  SL = entryPrice x (1 - 1.5 x ATR%)     // 价格下跌1.5倍ATR止损
  TP = entryPrice x (1 + 1.0 x ATR%)     // 价格上涨1.0倍ATR止盈
```

### 2.3 Layer 2: 程序端机制

**移动止损 (Trailing Stop)**

现有代码已有 `peakPnLCache` 和 `checkPositionDrawdown` 机制，但仅用于监控。建议改为主动执行:

```
当仓位PnL > 5%保证金时，激活追踪止损:
  止损线 = 峰值PnL x 60%
  例: 峰值+10%，回撤到+6%时平仓

当仓位PnL > 10%保证金时，收紧追踪:
  止损线 = 峰值PnL x 70%
  例: 峰值+15%，回撤到+10.5%时平仓
```

与现有 `TradingRules.ExitSignals.TrailingStop` (峰值回撤30%平仓) 配合使用。

**时间止损**

反向策略应有时间限制:
```
持仓超过4小时: 不管盈亏，触发平仓评估
  - 如果盈利: 收紧追踪止损至峰值80%
  - 如果小幅亏损(< 3%保证金): 直接平仓
  - 如果大幅亏损(> 3%保证金): 等待SL触发

持仓超过8小时: 强制平仓
  - 反向策略不应长期持仓
  - 避免隔夜风险（资金费率等）
```

时间止损可以利用现有 `positionFirstSeenTime` 或数据库中的 `EntryTime` 计算。

### 2.4 Layer 3: AI平仓信号

AI的平仓建议（close_long/close_short）**不反向执行**:
- 如果AI说close当前持仓方向 → 正常执行close
- 如果AI说close反方向（不存在的仓位） → 忽略
- AI的平仓信号受现有 `MinHoldMinutes` 和 `EmergencyCloseLossPct` 约束

## 3. 追踪止盈的具体方案

### 3.1 阶梯式追踪止盈

```
阶段1: PnL 0% ~ 3%（保证金）
  - 不追踪，依赖SL保护
  - 如果触发SL，接受亏损

阶段2: PnL 3% ~ 8%
  - 激活追踪: 止损移至保本点 (entry price)
  - 保护: 至少不亏损

阶段3: PnL 8% ~ 15%
  - 追踪收紧: 止损 = 峰值PnL x 50%
  - 例: 峰值+12%，止损在+6%

阶段4: PnL > 15%
  - 最紧追踪: 止损 = 峰值PnL x 70%
  - 考虑部分平仓获利
```

### 3.2 部分平仓策略

现有代码支持全部平仓 (`CloseLong(symbol, 0)`)，需要扩展支持部分平仓:

```
PnL达到10%: 平仓50%，剩余持有
PnL达到15%: 平仓剩余部分
或PnL从峰值回撤30%: 平掉全部
```

但注意: 反向策略的TP距离较近（1倍ATR），可能很少触及高阶止盈。简单的全仓SL/TP可能就足够了。

## 4. 利润保护机制

### 4.1 保本止损

当仓位盈利超过一定阈值后，将SL移至入场价:
```
条件: unrealizedPnL% > 3% (基于保证金)
动作: 更新交易所端SL至 entryPrice +/- 小buffer(0.1%)
效果: 锁定至少不亏损
```

这需要调用 `trader.SetStopLoss()` 更新SL价格。现有代码没有"更新SL"的逻辑，需要新增。

### 4.2 日利润保护

```
当日已实现盈利 > 5% 权益时:
  - 新开仓仓位减半
  - 加宽冷却时间至 CooldownMinutes x 2
  - 目的: 保护当日利润，避免贪婪导致回吐
```

### 4.3 资金费率影响

永续合约持仓需考虑资金费率（每8小时收取一次）:
- 做多时资金费率为正: 持仓方付费（不利）
- 做空时资金费率为正: 持仓方收费（有利）
- 反向策略会改变资金费率的方向影响

建议:
- 将资金费率纳入平仓决策
- 如果资金费率对持仓方向不利且绝对值 > 0.1%，作为提前平仓的参考因素
- 现有策略配置中 `EnableFundingRate: true` 已包含此数据

## 5. 与现有风控机制的交互

### 5.1 MinHoldMinutes

现有: 120分钟（2小时）内不允许AI主动平仓
反向策略建议: 60分钟

理由:
- 反向策略的持仓时间预期更短
- 但仍需防止过度频繁平仓
- `EmergencyCloseLossPct` 可以绕过此限制

### 5.2 CooldownMinutes

现有: 180分钟（3小时）同币种冷却
反向策略建议: 240分钟（4小时）

理由:
- 反向策略更需要"观望"而不是频繁进出
- 避免同一币种上反复反向交易
- 给市场足够时间发展新趋势

### 5.3 EmergencyCloseLossPct

现有: -20% 保证金PnL
反向策略建议: -15% 保证金PnL

理由:
- 反向策略的SL距离更远，需要更早的紧急退出
- 配合降低的杠杆，-15%仍然给予足够的波动空间
- 但在SL失效（网络问题等）时提供额外保护
