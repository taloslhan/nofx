# 系统性风险与监控报警

## 1. 系统性风险分析

### 1.1 AI模型更换/更新风险

**风险描述**: AI底层模型（DeepSeek/Qwen）升级后，错误率可能从90%降低

| 风险场景 | 概率 | 影响 | 风险等级 | 缓解措施 |
|---------|------|------|---------|---------|
| 模型小版本更新 | 高(每月) | 低(误差<5%) | 中 | AI准确率监控自动检测 |
| 模型大版本更新 | 中(每季度) | 高(误差可能>20%) | 高 | 更新后暂停策略，回测确认 |
| 模型接口变更 | 低 | 高(解析失败) | 高 | 现有error handling覆盖 |
| Prompt格式变化影响 | 中 | 中 | 中 | 定期检查AI输出质量 |

**应对方案**:
- 建立AI模型版本追踪（记录每次调用的模型版本）
- 模型版本变化时自动触发"观察模式"（仅模拟不执行）
- 回测最近50笔决策在新模型下的方向是否变化

### 1.2 市场Regime变化

**风险描述**: 市场从一种状态切换到另一种，AI的错误模式可能改变

| 市场状态 | AI可能的错误模式 | 反向策略表现 |
|---------|----------------|------------|
| 强趋势（单边） | 追涨杀跌，方向错误 | 反向策略表现良好 |
| 震荡区间 | 频繁假突破，可能偶尔正确 | 反向策略表现一般 |
| 极端行情（暴跌） | 恐慌性判断，可能反应正确 | 反向策略可能亏损 |
| 低波动窄幅 | 随机判断，正确率接近50% | 反向策略无优势 |

**应对方案**:
- 监控市场波动率(ATR/VIX等)，低波动时减半仓位
- 极端行情时暂停策略（BTC 1小时涨跌 > 5%）
- 震荡市场中增加冷却时间，减少交易频率

### 1.3 交易所风控（强平）与反向策略的交互

**风险描述**: 反向策略的SL距离更远，更容易接近强平价

当前的仓位限制:
```
BTC/ETH: 仓位 <= equity x 2.0 (建议值), 杠杆 3-5x
强平距离: 约 20-33% 价格波动 (1/leverage * 维持保证金率)
SL距离: 约 1.5 x ATR(14) ≈ 2-4% (BTC日内)
```

强平与SL的安全距离:
```
3x杠杆: 强平距离 ~30%, SL距离 ~4% → 安全裕度 26%
5x杠杆: 强平距离 ~18%, SL距离 ~4% → 安全裕度 14%
10x杠杆: 强平距离 ~9%, SL距离 ~4% → 安全裕度 5% (危险!)
```

**结论**: 反向策略不应使用10x杠杆，5x是上限，3x最安全

### 1.4 流动性风险

**风险描述**: 山寨币流动性差，大单可能造成严重滑点

| 风险因素 | BTC/ETH | 主流山寨 | 小市值山寨 |
|---------|---------|---------|-----------|
| 滑点估计 | < 0.05% | 0.1-0.3% | 0.3-1.0% |
| SL执行偏差 | 可忽略 | 小 | 可能显著 |
| 反向策略影响 | 低 | 中 | 高 |

**应对方案**:
- 小市值山寨币使用更小仓位（AltcoinMaxPositionValueRatio: 0.5）
- 避免在深夜（流动性最差时段）交易山寨币
- 使用限价单代替市价单（需要代码改造）

## 2. 监控指标清单

### 2.1 实时监控指标

| 指标 | 计算方式 | 检查频率 | 正常范围 |
|------|---------|---------|---------|
| AI准确率(50笔窗口) | 反向亏损笔数/总笔数 | 每笔交易后 | < 20% |
| 连续亏损计数 | 当前连续亏损笔数 | 每笔交易后 | < 3 |
| 日累计PnL | 当日已实现+未实现PnL | 每分钟 | > -5%权益 |
| 周累计PnL | 本周累计PnL | 每小时 | > -10%权益 |
| 保证金使用率 | totalMarginUsed/equity | 每周期 | < 60% |
| 最大单仓回撤 | 峰值PnL - 当前PnL | 每分钟 | < 10%保证金 |
| 账户权益趋势 | 滑动平均斜率 | 每小时 | 正斜率 |

### 2.2 衍生监控指标

| 指标 | 计算方式 | 意义 |
|------|---------|------|
| 滚动胜率 | 最近20笔的胜率 | 短期策略有效性 |
| 滚动期望值 | avg(win) x winrate - avg(loss) x lossrate | 策略盈利能力 |
| 夏普比率(滚动) | 收益均值/收益标准差 | 风险调整后收益 |
| 最大回撤(从峰值) | (peak_equity - current_equity)/peak_equity | 策略健康度 |
| 平均持仓时长 | 所有平仓交易的持仓时长均值 | 策略节奏 |
| 交易频率 | 每日交易笔数 | 过度交易检测 |

## 3. 报警阈值与通知

### 3.1 AI准确率报警

| 阈值 | 级别 | 通知方式 | 动作 |
|------|------|---------|------|
| AI准确率 > 20% | INFO | 系统日志 | 记录，不干预 |
| AI准确率 > 25% | WARN | Telegram通知 | 新仓位仓位减半 |
| AI准确率 > 30% | ALERT | Telegram + 邮件 | 暂停新开仓 |
| AI准确率 > 33% | CRITICAL | 全渠道通知 | 平仓 + 停止策略 |

### 3.2 资金曲线异常检测

**方法: Z-Score检测**
```
计算最近20笔交易PnL的均值和标准差
如果单笔PnL < mean - 2*std → 异常亏损
如果连续3笔PnL < mean - 1*std → 趋势恶化
```

**方法: CUSUM检测**
```
累积偏差和 S_n = max(0, S_{n-1} + (loss_n - target))
当 S_n > threshold → 检测到策略恶化
```

### 3.3 账户权益曲线异常

| 异常类型 | 检测方法 | 阈值 | 动作 |
|---------|---------|------|------|
| 快速下跌 | 1小时内权益下降 | > 5% | L2暂停 |
| 持续下跌 | 连续3天权益下降 | 每日> 1% | WARN通知 |
| 从峰值大回撤 | drawdown from peak | > 15% | L3停止 |
| 权益归零风险 | 权益 < 初始50% | - | L4紧急 |

## 4. 人工审核触发条件

### 4.1 必须人工审核的场景

1. **AI准确率异常上升**: > 33%（策略基础假设失效）
2. **连续亏损 >= 4次**: 概率极低（0.01%），可能是系统性问题
3. **单笔超大亏损**: > 5%权益（SL失效或滑点异常）
4. **日亏损触及L3**: > 8%权益
5. **AI模型版本变更**: 需确认错误率是否变化
6. **交易所API异常**: 订单执行偏差 > 1%

### 4.2 人工审核流程

```
1. 收到CRITICAL级别通知
2. 系统自动暂停所有新交易
3. 保留/平掉现有仓位（取决于PnL情况）
4. 审核内容:
   a. 最近20笔交易记录
   b. AI决策日志和原始reasoning
   c. 市场状态（是否有regime变化）
   d. 账户权益曲线
5. 决策: 恢复/调参/停止
6. 手动解除暂停
```

- 支持通过Telegram命令暂停/恢复策略
